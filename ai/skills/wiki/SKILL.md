# Wiki

A knowledge base is compiled, not indexed. Raw sources go in once and become interlinked
articles that stay current; the alternative is rediscovering the same knowledge from the same
sources on every question. The bookkeeping that makes people abandon wikis — cross-references,
summaries, contradiction tracking — is the part a model does without fatigue.

The division of labour that follows from that:

- **You** decide what to ingest, what to ask, and which contradictions matter.
- **The model** summarises, cross-references, files, and flags inconsistency.
- **`wiki`**, the CLI, decides everything mechanical: link graphs, word counts, file hashes,
  dates. Never compute these by reading. `wiki` is on PATH and is the same command in
  every harness.

## Operations

| Request | Do this |
|---|---|
| `/wiki init [path]` | Read `references/init.md` |
| `/wiki ingest <source>` | Read `references/ingest.md` |
| `/wiki compile` | Read `references/compile.md` |
| `/wiki status` | Run `wiki status`. Print it. Nothing else |
| `/wiki lint` | Run `wiki lint`, then read `references/lint.md` for the three checks it cannot make |
| `/wiki promote` | Read `references/promote.md` |
| anything else | A question. Read `references/query.md` |

Locate the knowledge base with `wiki path`. It takes an explicit `--wiki DIR`, otherwise
walks up from the current directory to the repo root looking for one. Exit code 2 means
none exists — offer `/wiki init`, do not guess a location.

## What the CLI already knows

Run these instead of deriving the answer:

```bash
wiki status              # counts, uncompiled sources, recent activity
wiki lint                # nine mechanical health checks
wiki lint --json         # the same, for filtering
wiki sources --new       # sources that are new or changed since last compile
wiki index               # rebuild the master index from article frontmatter
```

`wiki sources` computes each source's sha256. **Never write a hash you did not get from
it** — a hash is unverifiable by inspection, so a plausible-looking wrong one silently
breaks incremental compilation rather than failing.

## Principles

1. **Merge over create.** Ten sources on one topic make one rich article, not ten thin
   ones. Only create when the concept is genuinely absent from the index.
2. **Split by concept.** The converse: one source covering architecture, failure modes and
   tooling is three articles, cross-linked — not one that is none of them.
3. **Synthesise, don't summarise.** Reformatting the source adds nothing. Connect it to
   what is already there and write something more useful than the original.
4. **Preserve specifics.** Numbers, dates, versions, error messages, ticket IDs. These are
   the difference between a wiki article and a generic summary.
5. **Flag contradictions, never overwrite.** Mark both sides and log it. Silently replacing
   a claim destroys the record of what changed.
6. **Never link to an article that does not exist.** Mention it in plain text and log the
   gap. A dead wikilink is a lint error, and `wiki lint` will find it.
7. **Quality gates on every write.** Nothing enters without passing `wiki lint`.

## Structure

```
SCHEMA.md     # what this wiki is about, and its settings — the existence marker
_index.md     # generated by `wiki index`; never hand-edit
_log.md       # append-only activity log
_sources.md   # source manifest with content hashes
raw/          # immutable sources, never edited after ingest
articles/     # compiled articles
drafts/       # awaiting promotion
archive/      # retired articles
meta/         # glossary, conventions
```

`SCHEMA.md` is what makes a directory a knowledge base, and it holds the settings `wiki`
reads (`min_article_words`, `staleness_threshold_days`). The index is generated: rebuild it
with `wiki index` rather than editing it.

## Safety

- `wiki` is read-only apart from `wiki index`, which writes only `_index.md`.
- Never edit anything in `raw/`. Sources are immutable; re-ingest instead.
- Never delete an article to resolve a lint finding. Fix the finding or archive the article.
- Report the counts `wiki status` gives. Do not estimate them from a directory listing.
